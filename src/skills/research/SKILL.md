# Research

Settle a factual question with evidence, not recall. Dispatch the reading to a background subagent so the main thread keeps working, then return structured findings where every claim traces to the primary source that owns it.

## Overview

Research answers a factual question that blocks a decision or a design. The output is not an essay: it is a structured set of findings, each cited to a **primary source**. A primary source is the artifact that owns the claim (the official docs, the source code, the spec, the first-party API), never a secondary write-up of it. Established fact and inference stay visibly separate, and anything that could not be verified is said so plainly.

## When to Use

- A factual question blocks a decision, a design, or an implementation.
- You need docs or API facts gathered, or reading legwork delegated.
- You want a claim verified before relying on it.
- The answer must be traceable to a source, not taken on recall.

## Process

### 1. State the question

Turn the topic into the specific factual questions that would settle it. Name, for each, what evidence would count as an answer. A question with no observable answer is not research.

### 2. Dispatch a background subagent

Hand the search to a background subagent so the main thread keeps working while it reads. Give it the question and the source strategy, and ask for findings, not prose.

If the harness has no background subagent, **degrade to a foreground lookup**: do the same search yourself and return the same structured findings. Never skip the research or fail because the background path is unavailable.

### 3. Investigate primary sources

Read the artifact that owns each claim: official docs, source code, upstream repositories, specifications, first-party APIs. Follow every claim back to that owner. A secondary write-up is a lead, not a source.

### 4. Cite every claim

Attach a primary source to every claim, as a URL or a file path. A claim with no source is not a finding.

### 5. Separate fact from inference

Mark what the source establishes as fact, and mark your own reasoning as inference. Never let inference wear the clothes of established fact.

### 6. Return structured findings

Report the answer as a structured list of claims, each with its source and its fact/inference label. State plainly what could not be verified, and why. Do not bury the result in prose opinion.

## Gates

- **Every claim has a primary source.** No source, no finding.
- **Fact and inference are labeled.** Inference is never presented as established fact.
- **Unverified is stated as unverified.** A question that could not be answered is reported, not dropped.
- **Degrade, do not fail.** With no background subagent, run the lookup in the foreground and return the same findings.

## Anti-patterns

- Citing a secondary write-up instead of the source that owns the claim.
- Returning uncited claims or prose opinions.
- Presenting inference as established fact.
- Silently dropping a question that could not be verified.
- Skipping the research, or failing, when no background subagent is available.
- Answering from recall when a primary source is reachable.
