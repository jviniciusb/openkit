# Skill recipe rubric

The house style and taste constraints for a derived kit skill. Read this before drafting.

## Description discipline

- `description` states only *when* to use the skill (its triggers), never the workflow.

## Structure

- Overview / core principle, When to Use, Process, Gates, Anti-patterns.
- Keep it lean; scale the artifact to the task.

## Context engineering

- Context pointers over restatement.
- Progressive disclosure: in-file step, then in-file reference, then `references/`.
- Leading words.
- Positive phrasing.
- No em-dashes.

## Taste constraints (explicit non-goals)

- No TDD red-green-refactor ceremony.
- No separate plan file.
- No glossary/ADR requirement.
- No mandatory issue tracker.
- No enforced multi-skill chains.

## Required behaviors

- The spec (or brief) is the contract.
- Subagent-per-task with an independent reviewer.
- Parallel execution where tasks are independent.
- Human gates at consequential seams.

## Provenance block format

End the body with:

```html
<!-- generated by skill-recipe
     from: <repo>@<commit> <path>
     license: MIT (dev-only snapshot: skill-sources/<name>/LICENSE in the repo) -->
```

The `skill-sources/<name>/LICENSE` pointer is the vendored-snapshot case; when the sources are arbitrary or local, point the license at wherever that source actually lives.
