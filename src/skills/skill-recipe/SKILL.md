# Skill Recipe

Turn a brief plus one or more source skills into a self-contained kit-style `SKILL.md`. The brief is the contract: honor its intent, its keep/drop guidance, and its desired structure.

On activation, announce **"Using the skill-recipe skill."** then begin the process.

## Overview

A kit skill is declarative: a directory holding `SKILL.md`, plus one barrel line in `src/skills/index.ts`. This recipe reads the brief, reads the named sources, reads [rubric.md](rubric.md), then drafts the new skill in the kit house style. It never invents content and never clobbers an authored file.

## When to Use

- The author asks to derive a new kit skill from a brief and named sources.
- The author invokes `@skill-recipe`, or says "use the skill recipe".

## Process

### 1. Read the brief

The brief carries the target id, trigger/description, intent, source paths, keep/drop guidance, and desired structure. A starting point lives in [brief-template.md](brief-template.md).

Read [rubric.md](rubric.md) before drafting. It holds the house style and the taste constraints.

### 2. Validate every named source

Resolve each source path the brief names. If a source id is unknown or absent on disk, **refuse to synthesize**. Name the missing source, stop, and ask the author to correct the brief. Never substitute your own memory for a missing source, and never invent that source's content.

### 3. Read the sources

Read each named source in full. Extract only what the brief says to keep; drop what it says to drop. Keep the output self-contained: remove every reference to an external kit or skill, including `plugin:skill` prefixes that belong to another kit. The provenance comment from Step 7 is the sole exception: it is the one allowed place to name a source repo.

### 4. Draft the SKILL.md

Write `src/skills/<id>/SKILL.md` in the kit house style: frontmatter with `name` and a trigger-only `description`, then Overview / core principle, When to Use, Process, Gates, Anti-patterns. Scale the artifact to the task.

### 5. Show the draft

Present the drafted file, or the diff when the target already exists. Wait for the author's response before writing. Never overwrite a hand-edited or previously generated file without explicit confirmation.

### 6. Add the barrel entry

Insert the skill between the `<kit:skills>` markers in `src/skills/index.ts`, in the shape `openkit new skill <id>` produces:

```ts
defineSkill({ id: "<id>", dir: new URL("./<id>/", import.meta.url) }),
```

Add `autoinvoke: false` when the skill should stay hidden from the model's advertised list.

### 7. Provenance

End the body with a provenance comment that names each source repo, commit, and path, and the license:

```html
<!-- generated by skill-recipe
     from: <repo>@<commit> <path>
     license: MIT (dev-only snapshot: skill-sources/<name>/LICENSE in the repo) -->
```

The `skill-sources/<name>/LICENSE` pointer is the **vendored-snapshot** case: it applies when the source was vendored into `skill-sources/`. When the sources are arbitrary or local, point the license at wherever that source actually lives instead.

### 8. Add a test

Write `tests/unit/<id>.test.ts`, mirroring `tests/unit/interview.test.ts`: assert the barrel entry resolves (the skill is found in `skills` with the expected `autoinvoke`) and that the `SKILL.md` frontmatter parses with the right `name` and a `description`.

### 9. Add the example entry

Add the new skill to `docs/examples/openkit.jsonc`, in the shape the existing entries use.

Then run `bun run typecheck && bun test`.

## Gates

- **Unknown or absent source id:** refuse and ask. Do not synthesize.
- **Existing target file:** show the diff and get explicit confirmation before overwriting.
- **Before finishing:** `bun run typecheck && bun test` pass.

## Anti-patterns

- Inventing content for a source the brief names but the repo does not contain.
- Writing the file before showing the draft.
- Overwriting an authored or generated file without explicit confirmation.
- Leaving external kit references in the output.
- Letting `description` describe the workflow instead of when to use the skill.
